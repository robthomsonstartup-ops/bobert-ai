# Bobert Sales OS

## Purpose
Bobert is the operating layer for how Rob finds, qualifies, researches, communicates with, and advances business. External platforms are tools. They do not define the workflow.

## v0.1 foundation
- Today / Command Center: what should I work on?
- Work queue: Attack Now, Follow Up, Research, Nurture, All
- Account record: identity, people, opportunities, intelligence, evidence, conversations, activities, strategy, next action, history
- Evidence first: screenshots, emails, URLs, articles, notes and other source material can support facts
- Verified vs inferred: inferred intelligence is never silently presented as fact
- Next action is explicit so work does not disappear into a CRM activity log
- Raw HubSpot CSV import without requiring a HubSpot integration
- Existing Capture, Field, Market and other Bobert modules remain intact

## Core principle
The OS owns the process. HubSpot, Apollo, email, web research and AI models are tools that feed or execute against the OS.

## Build order
1. Account + evidence data model
2. Import current Working Accounts
3. Universal capture: email / screenshot / URL / note
4. Intelligence extraction and source linking
5. Daily work queue and next-action engine
6. Conversation and follow-up workflow
7. Research / market signal engine
8. Integrations only where they remove meaningful manual work

## Truth model
Every material claim should carry:
- source
- source type
- date captured
- account/person relationship
- confidence or verification state

Bobert may make recommendations and inferences, but it must keep those distinct from verified facts.
